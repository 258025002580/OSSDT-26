# Assignment1：开源项目调研与第一次PR

**分值：5分｜完成方式：个人独立完成｜截止时间：12月1日下午18:00**

## 一、作业目标

- 通过阅读项目仓库，了解开源软件的用途、许可证、维护情况和参与方式。
- 使用Markdown编写一份简短的调研报告。
- 向课程仓库提交一次Pull Request（PR），体验开源协作流程。

## 二、作业要求

### 1. 选择一个开源项目

选择一个你感兴趣、具有明确开源许可证的GitHub项目。规模和编程语言不限，建议选择**自己使用过或能够理解其用途**的项目。不同同学可以选择同一项目，但须独立调研和撰写。

本次作业不要求安装运行项目或修改其代码。

### 2. 撰写调研报告

使用自己的语言，围绕以下内容完成Markdown报告，建议正文600—1000字，表格与链接不计入字数；字数仅作参考。

| 内容           | 具体要求                                                                                                 |
| -------------- | -------------------------------------------------------------------------------------------------------- |
| 基本信息与用途 | 给出项目名称、仓库链接和调研日期；说明项目解决什么问题、面向哪些用户，以及你选择它的原因                 |
| 开源许可证     | 阅读许可证文件，写明许可证名称并给出链接；简述一项使用、修改或再分发时需要注意的义务                     |
| 维护与活跃情况 | 观察近期Commit、Release、Issue或PR，至少从两个方面举例说明维护情况，提供日期或链接；不要仅凭Star数量判断 |

### 3. 向课程仓库提交PR

通过PR将调研报告提交到课程仓库本文件夹下。默认创建PR的GitHub账号为你的GitHub账号。

**本次PR的目标是提交你的调研报告，不是向被调研的开源项目提交代码。**

## 三、提交方式

### 1. 文件命名

每人提交一个独立Markdown文件，以**学号后6位**命名。

### 2. 操作流程

可以使用Git命令行、GitHub网页或图形客户端完成，流程如下：

1. 将教师的 `OSSDT-26` 仓库Fork到自己的GitHub账号。
2. 在自己的Fork中创建作业分支，例如 `assignment1-report`。
3. 在 `assignments1/` 下新建个人Markdown文件，完成报告并提交Commit。
4. 向教师课程仓库的默认分支发起PR，来源为自己Fork中的作业分支。
5. 检查PR中的变更，确保只新增自己的报告，没有修改课程说明或其他同学的文件。
6. 如收到修改意见，在同一个作业分支继续提交修改，已有PR会随之更新，无须重复创建。

PR标题位：

```text
Assignment1：<学号后6位>—<调研项目名称>-调研报告
```

PR说明中写明调研项目名称和报告文件路径即可。每人保留一个有效提交PR；是否合并由教师处理，**不以教师在截止前完成合并作为按时提交的条件**。报告无需额外提供PR截图，其提交记录和PR本身即为操作证据。

## 四、报告模板

将以下内容复制到个人Markdown文件中，替换提示文字，保留章节标题。

```markdown
# Assignment1：开源项目调研

- 个人标识：<学号后6位>
- 项目名称：
- 仓库链接：
- 调研日期：YYYY-MM-DD

## 1. 项目用途与选择原因

说明项目的主要用途、目标用户，以及选择该项目的原因。

## 2. 开源许可证

写明许可证名称和文件链接，说明一项需要注意的义务。

## 3. 维护与活跃情况

至少从两个方面提供观察依据，并给出相关日期或链接。
结合这些证据说明你的判断；证据有限时说明局限。

## 4. 参考资料与工具使用

列出主要参考链接。如使用AI工具，简要说明用途及人工核查方式；
未使用则注明“未使用AI工具”。
```

## 五、评分标准

| 评分项             | 评价依据                                                               |  分值 |
| ------------------ | ---------------------------------------------------------------------- | ----: |
| 项目用途与选择原因 | 用途、目标用户和选择原因清楚，有项目资料作为依据                       |     1 |
| 开源许可证         | 许可证名称及义务说明准确，提供许可证文件链接                           |     1 |
| 维护与活跃情况     | 至少两个方面的具体证据，判断与证据相符                                 |     1 |
| PR操作             | 向正确的课程仓库与分支提交PR，能够根据反馈在原PR中更新                 |     1 |
| 提交规范           | 文件位置与命名正确，只提交个人报告；内容完整，Markdown可读，链接可核查 |     1 |
| **合计**           | **调研内容3分，PR与提交规范2分**                                       | **5** |

调研内容由教师与助教人工核查。允许使用AI工具辅助理解和表达，但必须自行查阅项目资料、核查事实并说明使用方式，不得编造许可证、维护记录或贡献经历。

- [ ] 文件位于 `assignment1/`，使用正确的个人标识命名。
- [ ] PR提交到教师课程仓库，变更仅包含自己的报告。
- [ ] Markdown预览正常，没有残留模板提示。
